# הפעלה מקומית עם SQLite

שרת ה־Web המקומי פועל ללא D1. שירות Python נשאר נפרד ומספק את הליבה ומתאם InfluxDB ברשת הפנימית. ההדגמה הציבורית אינה כוללת חיבור לשרת Influx של הלקוח.

## הכנה במחשב פיתוח

1. התקן Node בהתאם ל־package.json והתקן תלויות מה־lockfile.
2. הרץ `npm run build:offline` והעבר את `.next/standalone`, את `.next/static`, את `public` ואת `scripts/start-offline.mjs` באותו מבנה תיקיות למחשב היעד, עם Node מותקן מראש.
3. במחשב היעד הרץ `node scripts/start-offline.mjs`. אין בשלב זה התקנת חבילות או צורך באינטרנט. ברירת המחדל היא האזנה למחשב המקומי בלבד.
4. SQLite נוצר ב־`data/bluewolf.sqlite`. ניתן לשנות באמצעות `BLUEWOLF_SQLITE_PATH`. כל הדפדפנים בהתקנה המקומית חולקים את סביבת `installation`.
5. התקן את Python באמצעות `deploy/windows/install-runtime.ps1` עם wheelhouse מקומי. חבילות Windows חייבות להתאים לגרסת Python ולארכיטקטורת מחשב היעד; חבילות Linux אינן תחליף להן.
6. הגדר `BLUEWOLF_CORE_API_URL` לכתובת השירות המקומי. הפעלה מבצעית דורשת את התצורה התפעולית ואת טוקן Influx במשתנה הסביבה המתאים.
7. כדי שהליבה תקרא את שמות עמודות ה־Join שנשמרו ב־Web, הגדר בשירות Python את `BLUEWOLF_WORKSPACE_DB` לנתיב המלא של מסד ה־Web. הקריאה מתבצעת בעת הפעלת השירות. שינוי השמות דורש הפעלה מחדש של שירות הליבה.

## גבולות המימוש שנבדק

שמירת תצורה ויומן ב־SQLite נבדקה בכתיבה, קריאה וקונפליקט גרסאות. הדפדפן אינו מפעיל שינוי שנכשל בשמירה. הארכיון של דגימות Python תומך בקריאה באצוות ובגרסה עקבית לאורך הקריאה.

מפת ההנדסה אינה תלויה במפת רקע חיצונית. מפה אמיתית מחייבת אריחים מקומיים או שרת מפות פנימי; אין הורדה אוטומטית של מפת העולם. יש לבדוק חבילת התקנה מלאה על Windows מנותק לפני קבלה מבצעית.

העקבה המבצעית ב־Web שומרת עד 30 דקות שנצפו בדפדפן. היא אינה מחברת פערים מעל 10 שניות או אירועים שונים. שחזור עקבה לאחר רענון מתוך ארכיון השרת עדיין אינו מחובר. חיבור מלא של כל תצורות הממשק, SI מבצעי ותחקור היסטורי מלא מחייבים המשך אינטגרציה; אין להציג את הדמו כאילו הם הושלמו.
