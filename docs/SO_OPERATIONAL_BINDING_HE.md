# SO · חוזה קשירה תפעולית בין Workspace, SQLite ו־Python Core

סטטוס: מימוש חלקי בענף `work/requirements-governance-2026-09-15`. מסמך זה מפרט את חוזה האינטגרציה הטכני ואינו מהווה אישור מוצר, אישור גרסת QA או תחליף ל־Master ולמסמך המחקר הפעילים ב־Google Drive.

## מקור האמת וחלוקת אחריות

תבנית `so-direct.v2` הנשמרת ב־Workspace וב־SQLite מכילה אך ורק שרשרת Single/Double, מיקום יחסי (חצי או רבע), כיוון נסיעה, ויחסים הנגזרים מהמיקומים. **אין לשמור בתבנית מזהה רכב, סוג רכב, מהירות עבודה או שיוך רכבים לקבוצת זמן־אמת.** מיפוי סוגי הרכב ו־Route Instances הוא מידע תפעולי נפרד ואינו משנה את התבנית שהמשתמש צייר.

קובץ התצורה התפעולי הנקוב ב־`BLUEWOLF_OPERATIONAL_CONFIG` מכיל מערך מפורש `soTemplateBindings` המסופק ומנוהל בנפרד מן ה־Workspace. כל רשומה מזהה `templateId` קיים, `routeInstanceIds` לפי סדר השרשרת, ו־`slots` הממפים כל `placementIndex` (האינדקס בתבנית השמורה) ל־`slotId` ייחודי ול־`vehicleType` מפורש. ב־`servers[].groups` קיימים בנפרד ה־Route Instances וקישור מספרי הרכב, סוגיהם ומהירות העבודה שלהם. הגשר בקובץ `lib/so-runtime-config.ts` בודק התאמה שלמה לפני כתיבת תבנית Core מסוג `templates[].routes[].slots[]`.

דוגמה לצורת הקשירה בלבד (אין להשתמש בה כמיפוי פריסה או כנתוני אמת):

```json
{
  "soTemplateBindings": [{
    "templateId": "so-direct-alpha",
    "routeInstanceIds": ["actual-route"],
    "slots": [
      { "placementIndex": 0, "slotId": "front", "vehicleType": "TYPE_A" },
      { "placementIndex": 1, "slotId": "back", "vehicleType": "TYPE_A" }
    ]
  }]
}
```

הדוגמה אינה מכילה מספרי רכב ואינה יכולה לפעול לבדה. `servers[].groups[].members[]` דורש שיוך מפורש ורשומת מדידה מ־Influx לכל מספר רכב; אסור לגזור שיוך מנתיב, ממהירות או מהמספר עצמו.

## התאמה מבנית מחייבת לבנק הליבה

גשר התבניות חייב למצוא לפחות קבוצת Core מוגדרת אחת ש־**כל** הרכב המסלולים והרכבים שלה תואם לתבנית המקושרת, ולא רק תת־קבוצה מקרית. זהות ומספר ה־Route Instances, סוגי Single/Double, כמות המשתתפים והתפלגות סוגי הרכב בכל Route Instance חייבים להיות זהים; נדרשים מספרי רכב ייחודיים ומהירויות עבודה חיוביות וסופיות. קבוצת Core שיש בה היפודרום נוסף, משתתף נוסף או אותו מספר רכב פעמיים אינה ראיה שתבנית ה־SO תיבחר ותפעל באותה קבוצה, ולכן אינה מתקבלת כמיפוי תפעולי תקין. התאמה זו היא תנאי מוקדם בלבד: גם התאמה מבנית מלאה אינה הוכחת בחירה, ציון או אירוע חי בליבה.

## חסימות מחייבות

1. תבנית SO ישירה ללא `soTemplateBindings` מפורש מדווחת כחסרה ואינה מתווספת בשקט לבנק הליבה; תבניות Core ותיקות שאינן תחת הקשירה הזאת אינן מוחלפות. קשירה חלקית, מיקום כפול, Route Instance חסר, סוגי רכב סותרים או היעדר קבוצת רכב מוגדרת גורמים לכישלון סנכרון, לא לנתונים מומצאים.
2. כיוון `reverse` נשמר ב־SQLite, אולם מודל ה־slot התפעולי הנוכחי של Python Core אינו אוכף כיוון־למיקום. לכן הגשר דוחה בשלב זה ניסיון לטעון מיקום `reverse` כביכול לתבנית Core חד־כיוונית. השלמת התמיכה דורשת שינוי מודל ה־Core ובדיקות פיזיקליות של פאזה/כיוון לפני שחרור.
3. כתיבת קובץ קונפיגורציה אטומית אינה מוכיחה שה־Core רץ עם הגרסה החדשה. נדרשים restart מבוקר, חותמת גרסת קוד ותצורה, בדיקת קבוצות ומסלולים מזוהים, ציונים ואירועים מה־Core בפועל, ושחזור ארכיון ו־PDF מאותה עדות.
4. בדיקת QA קצה־לקצה מחייבת בנוסף Web ו־SQLite באותו קובץ, תצורת Influx מאובטחת ומחוברת לשלושת השרתים, דגימות מתקדמות בזמן מקור, בחירה והחלה של תבנית SO/‏SI וגרפים/מפה/תחקור עקביים. אין לפרסם קישור QA מלא על סמך build, HTTP 200, בדיקות יחידה או תצוגת SIM.

## מצב נוכחי

מסלול הגשר ותיקוף הקשירה קיימים בקוד ומכוסים בבדיקות דטרמיניסטיות; ממשק קשירה מלא, כיוונים הפוכים ב־Core, התאמת תצורות קיימות של לקוח, אימות טעינה מחדש ובדיקת Influx↔Core↔SQLite↔Web חיה טרם הושלמו. `BW-GOV-010` נשאר חסום עד סקירה הנדסית של השינויים מול ה־Master ומסמך המחקר המקוריים, ולא ייסגר על ידי החלפת טביעת אצבע טכנית בלבד.
