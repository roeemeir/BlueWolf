# זאב כחול — שער מחייב למסירת גרסת בדיקות E2E

עודכן: 23/09/2026. מסמך זה כפוף ל־Master המקורי ב־Google Drive (נספח QA-E2E-20260923) ולמסמך המחקר הפעיל v1.2 (נספח ד). הוא אינו מהווה ראיית מימוש או אישור להפצה. הוראה זו מחליפה כל הוראה קודמת שהתירה פרסום קישור QA מוקדם לאחר build/HTTP 200 בלבד.

## מדיניות בלתי ניתנת לעקיפה

**אין לפרסם למשתמש שום URL של גרסת בדיקות, גם לא Preview זמני, עד שבאותה סביבת ריצה ובאותו HEAD אומתו בהצלחה Web + SQLite + Python Core תפעולי + מקור ניווט InfluxDB2 מזין + תהליכי אירועים, ארכיון, תחקור ו־PDF.** אין להציג שירות QA (`bluewolf-runtime` במצב `transport-only`), יצירת HTML או SIM בצד הלקוח כהוכחה לחיבור Core. קישורים קודמים שנוצרו ללא השער אינם גרסאות קבלה; אין להפנות אליהם עוד. CI ירוק לבדו אינו מוכיח E2E; כשל `BW-GOV-010` ממשיך לחסום שחרור גם אם בדיקות היחידה עברו.

## תנאי PASS מינימליים לפני יצירת URL artifact

1. Core מוגדר עם `BLUEWOLF_OPERATIONAL_CONFIG`, `BLUEWOLF_INFLUX_TOKEN`, מקור נתונים וקובץ מצב/ארכיון בר־כתיבה. `/readyz` חייב להחזיר `mode=operational`, `running=true`, `tickCount>=2`, ללא שגיאות שרת; `/healthz` אינו מדד קבלה.
2. שלושת השרתים שהוגדרו במוצר מפיקים **דגימות חדשות מזמן המקור** דרך Influx adapter אמיתי. לכל שרת קיימים נתוני WGS84 תקינים, נתיב שה־Core זיהה, קבוצת SI/SO וציון שנוצר בפועל בליבה; הפסקת מקור חייבת להיראות כהיעדר נתון, ללא החלפה שקטה בסימולציה. נתוני בדיקה סינתטיים מותרים רק אם הוזרמו למקור הנתונים ועברו את אותו Core, ומסומנים בבירור כנתוני בדיקה.
3. Web/SQLite: שמירת הגדרות שרת/קבוצה, תבנית ובנק נתיבים; קריאה מחדש בדפדפן שני, טיפול בקונפליקט גרסאות ו־restart של Core/Web/SQLite תוך שמירת ההגדרות והראיות. בחירת תבנית SI/SO חייבת לעדכן קובץ ההגדרות התפעולי המשותף ולייצר תוצאות Core תואמות ולא רק הודעת ״נשמר״.
4. אירוע מאומת: נתיב מזוהה מהליבה, זיהוי קבוצתיות, ציוני הרכב/קבוצה, עקבות מקור על המפה, סמן זמן משותף לגרף, ארכיון, החלת תבנית מתחילת האירוע, שחזור אותו eventId+version ותחקור/PDF בעברית המבוססים על אותן דגימות. כל רכיב חסר חוסם את כל פרסום הגרסה.
5. בדיקות ממשק דפדפן ואייפון במצב חי: SI מציג רק הפרשים בין סמוכים עם ציור קוהרנטי; SO מציג כל רכב על ההיפודרום וחץ ההתקדמות; רכבים תמיד גלויים במפה ואין בוררי ״בסיס״/״קבוצות״; הודעות סיבה בעברית; עקבות בתחקור כ־scatter, מפות אירועים ונתיבים ביחס צירים שווה; בנק נתיבים על מפה עם גרירה, הוספה, עריכת WKT לפי דרישה; שלושה שרתים בעלי תרחישים שונים ומשתנים; מסך הגדרות מותאם iPhone. סעיף לא מאומת הוא חסם ולא ״מגבלה״ שניתן לפרסם לצדו קישור QA.
6. רק אחרי PASS מלא ותיעוד בדיקות עם exact source HEAD, נתוני מקור (ללא סודות), גרסת config ותוצאות E2E מותר ל־Workflow לפרסם URL artifact. אין לפרסם על סמך 200/HTML בלבד או לפני השלמת בדיקות. אם הבדיקות נכשלו, מפרסמים סטטוס חסום בלבד, ללא URL.

## גבולות וסמכויות

אין להזין token של Influx או סודות מפה למסמכי עבודה, לארטיפקטים או ללוגים. אין לתקן fingerprint של BW-GOV-010 כדי להעביר CI; רק לאחר סקירת הקוד ושני המסמכים המקוריים. אין למזג ל־main, להפוך PR מ־Draft או לשחרר לייצור ללא אישור מפורש של בעל המוצר.

**מצב נוכחי בעת עדכון הדרישה:** Workflow `qa-quick-tunnel.yml` הפעיל בעבר שירות Core ללא operational config, ולכן עבר HTTPS smoke אך לא היה E2E. הוא חייב להיחסם עד לחיבור ואימות מלאים. המסמך אינו טוען שה־E2E כבר עובד.
